# boj CLI 설계

작성일: 2026-11-27

## 1. 왜 만드나

- 백준이 다시 운영을 시작한 걸 계기로, 문제 번호 하나로 풀이 파일과 예제를 만들고 바로 채점하는 도구를 만든다.
- 처음 사용자는 나 혼자다. 하지만 다른 사람도 설치해서 쓰도록 공개하는 것이 목표다. Maven 라이브러리처럼 "설치하면 바로 쓰는 도구"를 지향한다.
- 지금은 AI 챗에게 문제와 예제 파일 구성을 맡기고 있다. 이 도구는 그 일을 다음처럼 바꾼다.
  - **빠르다.** 몇 초면 끝나고 토큰이 들지 않는다.
  - **같은 입력이면 늘 같은 결과가 나온다.**
  - **예제를 백준 원문 그대로 가져온다.** AI가 옮겨 적다 공백이나 줄바꿈을 틀리는 일이 없다.
- 2026-11-27에 확인해 보니 공개된 백준 MCP 서버들은 solved.ac 검색이나 힌트 위주였다. 예제 입출력을 파일로 만들어 주는 도구는 찾지 못했다.

**어필 포인트**: 문제 번호를 입력하면 결정적으로 동작한다. 예제는 원문 그대로다. 채점이 내장되어 있어 Gradle이나 IDE 없이 돌아간다. 언어와 템플릿은 설정 파일로 바꿀 수 있다.

## 2. 목표 / 비목표 / 반목표

**목표**
- `boj <번호>`: 문제 폴더, 템플릿 소스, 예제 in/out 파일을 만든다.
- `boj test [번호]`: 컴파일한 뒤 모든 예제를 실행하고 결과를 판정한다.
- `boj copy [번호]`: 제출용 코드를 클립보드에 넣는다. 패키지 줄처럼 지정한 줄은 뺀다.
- `boj open [번호]`: 문제 페이지를 브라우저로 연다.
- 템플릿과 언어 정의는 사용자 설정 파일로 바꿀 수 있다.
- 첫 버전은 Java만 완성한다. 언어 구조는 처음부터 다언어로 만든다.

**비목표 (이번 범위 밖)**
- 백준 제출이나 로그인 자동화
- 인터랙티브 문제 지원
- 스페셜 저지 채점기 구현. 출력이 달라도 "직접 확인 필요"로만 표시한다.
- 힌트, 풀이, AI 기능
- 특정 강의나 개인 레포 구조. `week1`, `a2309` 같은 주차와 순서 값은 지원하지 않는다.

**반목표 (기능이 돌아가도 이러면 실패)**
- 사용자가 작성한 파일을 덮어쓴다.
- 쓰려면 Gradle, IDE, AI가 꼭 필요하다.
- 백준에 불필요하게 많은 요청을 보낸다.

## 3. 제약

- 백준 문제 페이지(HTML)를 파싱해 정보를 얻는다. 문제 정보 크롤링은 막혀 있지 않다고 사용자가 확인했다.
- 그래도 예의를 지킨다.
  - 문제당 요청은 1회로 한다.
  - 받은 정보는 로컬에 저장하고 다시 요청하지 않는다.
  - 도구 이름이 드러나는 User-Agent를 보낸다.
- 주 사용 환경은 macOS다. 공개 도구이므로 Linux와 Windows에서도 빌드되어야 한다.
- 컴파일러와 런타임은 사용자 컴퓨터에 있어야 한다. 도구는 호출만 한다.

## 4. 접근 방식

| 방식 | 장점 | 단점 | 결정 |
|---|---|---|---|
| **Rust 단독 CLI** | 명령이 가장 짧다(`boj 2309`). 단일 바이너리라 빠르다. 언어에 중립적이다 | Java 사용자도 따로 설치해야 한다 | **선택** |
| Gradle 플러그인(Kotlin) | Maven처럼 build.gradle 한 줄로 설치한다 | 명령이 길다(`./gradlew boj -Pn=2309`). Gradle 프로젝트 전용이다 | 탈락 |
| Kotlin JAR + Gradle task (초기 구상) | JVM 생태계 안에 머문다 | JVM 기동이 느리고 명령이 길다. 문제마다 Test.java를 만드는 구조는 불필요하다 | 탈락 |

선택 이유: 사용자가 Rust를 써 보고 싶어 했고, 짧은 명령을 원했다. 다언어 확장에도 가장 자연스럽다.

## 5. 설계

### 5.1 명령

```
boj 2309              # 생성. 이미 있으면 덮어쓰지 않고 경로만 출력하고, 빠진 예제 파일만 채운다
boj 2309 -l cpp       # 언어 지정
boj 2309 -t scanner   # 같은 언어의 다른 템플릿
boj test [2309]       # 번호를 생략하면 현재 폴더
boj copy [2309]
boj open [2309]
```

- 번호를 생략하면 현재 디렉터리에서 위로 올라가며 문제 폴더를 찾는다. 폴더 안 메타 파일로 판단한다.
- 종료 코드: 성공은 0, 채점 실패는 1, 도구 오류는 2.

### 5.2 기본 구조 (설정 없음)

```
2309/
  Main.java
  tests/
    1.in  1.out
    2.in  2.out
  .boj.toml           # 메타: 번호, 제목, 시간 제한, 스페셜 저지 여부, 언어
```

- 직접 추가한 케이스(예: `tests/my1.in`, `tests/my1.out`)도 이름 짝만 맞으면 채점에 포함한다.

### 5.3 설정

- 설정은 세 겹으로 쌓인다. 앞쪽이 우선이다.
  1. 프로젝트 설정 `.boj/config.toml`. 현재 폴더에서 위로 탐색해 찾는다.
  2. 전역 설정 `~/.config/boj/config.toml`. 플랫폼별 설정 폴더를 따른다.
  3. 내장 기본값
- 사용자는 바꾸고 싶은 키만 적는다.

```toml
default = "java"
path = "{{id}}"                 # 예: "src/main/java/p{{id}}"
tests = "{{dir}}/tests"

[lang.java]
file = "Main.java"
template = "java"               # templates/java.* 를 찾는다
compile = "javac -encoding UTF-8 --release 11 -d {{build}} {{file}}"   # 기본 11, 사용자가 8 등으로 덮어씀
run = "java -Xss256m -cp {{build}} {{main_class}}"
strip = ['^\s*package\s+[\w.]+;\s*$']
time = "x2 + 1s"                # 백준 언어별 추가 시간 근사
```

- 자리 표시자는 다음만 둔다.

| 자리 표시자 | 뜻 |
|---|---|
| `{{id}}` | 문제 번호 |
| `{{title}}` | 문제 제목 |
| `{{dir}}` | 문제 폴더 |
| `{{file}}` | 소스 파일 |
| `{{build}}` | 임시 빌드 폴더 |
| `{{package}}` | Java 패키지 이름 |
| `{{main_class}}` | 실행할 클래스. 패키지가 있으면 `패키지.Main`, 없으면 `Main` |

- `{{package}}`는 경로가 `src/main/java/` 아래일 때만 계산한다. 그 밖에서는 빈 값이고, 템플릿의 `package` 줄은 생략된다.
- `path`에 숫자로 시작하는 Java 패키지 이름이 들어가면 경고한다. 예: `src/main/java/{{id}}`.
- 템플릿을 찾는 순서는 다음과 같다.
  1. `.boj/templates/`
  2. `~/.config/boj/templates/`
  3. 내장 템플릿
- `-t 이름`을 주면 `java-이름.*`을 찾는다.
- 내장 언어
  - v1: Java
  - 다음 버전: C++, Python, Kotlin
- 새 언어는 사용자가 `[lang.x]` 블록 하나를 추가해서 쓴다.

### 5.4 예제 가져오기

- `https://www.acmicpc.net/problem/{id}`를 한 번 요청해서 다음을 파싱한다.
  - 제목
  - 시간 제한
  - 예제 입력과 출력 블록 전부
  - 스페셜 저지 표시
- 파싱 결과는 `.boj.toml`과 `tests/`에 저장한다. 그 뒤로는 네트워크를 쓰지 않는다.
- 문제가 없거나 네트워크 오류가 나면 이유를 보여 주고 종료 코드 2로 끝낸다. 템플릿만 만드는 `--offline` 옵션을 둔다.

### 5.5 채점 (`boj test`)

- 진행 순서
  1. 임시 빌드 폴더에 컴파일한다. 컴파일 오류는 그대로 보여 준다.
  2. 각 케이스를 새 프로세스로 실행한다.
  3. 시간 제한은 문제 제한에 언어 보정을 적용한 값으로 둔다. 넘으면 종료시킨다.
- 출력 비교는 백준 방식을 따른다. 줄 끝 공백과 파일 끝 빈 줄은 무시한다.
- 판정 종류

| 판정 | 뜻 |
|---|---|
| 맞음 | 출력이 일치한다 |
| 틀림 | 출력이 다르다. 기대값과 실제값의 첫 차이 줄을 보여 준다 |
| 시간 초과 | 시간 제한을 넘었다 |
| 런타임 에러 | 비정상 종료했다. 종료 코드와 stderr를 보여 준다 |
| 확인 필요 | 스페셜 저지 문제에서 출력이 다르다. 종료 코드 1로 친다 |

- 케이스별 실행 시간을 함께 출력한다.

### 5.6 `copy`, `open`

- `copy`: 소스에서 `strip` 정규식에 맞는 줄을 빼고 클립보드에 넣는다. 클립보드를 쓸 수 없는 환경이면 표준 출력으로 내보낸다.
- `open`: 기본 브라우저로 문제 페이지를 연다.

## 6. 테스트 전략

외부 통신과 파일 생성은 경계를 나눠 테스트한다.

| 층 | 방법 |
|---|---|
| HTML 파싱 | 백준 페이지 몇 개를 fixture로 저장해 순수 함수로 테스트한다. 예제 여러 개, 스페셜 저지, 빈 출력 예제 포함 |
| HTTP | `Fetcher` trait 뒤에 숨긴다. 테스트는 가짜 구현을 쓴다. 실제 요청 테스트는 `#[ignore]`로 분리해 수동으로 돌린다 |
| 설정·템플릿 | 병합 순서, 자리 표시자 치환, 패키지 이름 계산을 순수 함수로 테스트한다 |
| 파일 생성 | 임시 디렉터리에서 실행한다. 덮어쓰기 금지와 빠진 파일만 채우기를 검증한다 |
| 출력 비교 | 공백과 빈 줄 규칙을 표 기반 테스트로 확인한다 |
| 채점 실행 | 아주 작은 Java 프로그램으로 통합 테스트한다(맞음/틀림/시간 초과/런타임 에러). `javac`가 없으면 건너뛴다 |
| CLI 전체 | 바이너리를 실행하는 end-to-end 테스트로 종료 코드와 출력을 검증한다. 네트워크는 가짜 서버나 fixture를 쓴다 |

CI에서는 네트워크 없이 모든 테스트가 통과해야 한다.

## 7. 배포

- GitHub Releases에 macOS, Linux, Windows 바이너리를 올린다.
- Homebrew tap에 등록한다.
- `cargo install`도 지원한다.
- 바이너리와 crate 이름은 `boj`로 한다. crates.io에서 2026-11-27에 비어 있는 걸 확인했다.
- GitHub 레포는 `seungmin-park/boj-cli`다.

## 8. 진행 관리

- 이 설계의 기능을 세분화해 노션 DB로 관리한다. 열은 다음과 같다.
  - 기능
  - 상세 내용
  - 상태(미완/진행/완료)
  - 버전(v1/v2)
  - 테스트 여부
- DB는 설계가 승인된 뒤 구현 계획과 함께 만든다.

## 9. 빌더에게 맡기는 것 (내가 정한 사항 포함)

**내가 정한 것** (사용자 확인 필요)
- 기본 경로 `{{id}}`와 테스트 폴더 `tests/`
- 메타 파일 `.boj.toml`
- 종료 코드 규칙
- 출력 비교 규칙
- `--offline` 옵션
- Java 기본 명령의 `--release 11`과 `-Xss256m`. 사용자가 답을 안 줘서 추천안대로 정했다
- 시간 제한을 모르면 5000ms
- 스페셜 저지 불일치("확인 필요")는 종료 코드 1

**빌더 재량**
- 사용할 crate 선택. 후보는 clap, reqwest, scraper, serde/toml, arboard, open, tempfile, assert_cmd
- 출력 색상과 서식
- 내부 모듈 구성
